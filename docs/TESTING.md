# Testing

Run `npm test`, `npm run build`, then `npm run test:browser`. Install Chromium once with `npx playwright install chromium`. Raw output stays under ignored `test-results/`; no browser profile, device identity, machine path or old development history is included in release archives.

Release 0.4.0 passes 60 unit tests and 41 browser tests. Unit tests cover bounded settings and the 0.4 fields, preferences, built-in presets, merge and replace imports, exact/wildcard scopes, version migration, synchronous approval initiation, denial, duplicate requests, late grants, cancellation, durable intent recovery, parent/player authorization, overlapping removal, the reconcile fingerprint (no broadcast on settings edits), frame-registry writes, keyboard commands, badge reporting, the adaptive-performance governor and the content hint. Browser tests also fail on any console error from the controls frames (the 'postMessage target origin' error seen on YouTube). Approval unit tests use a Chrome API model. The installed Chrome Add → Allow flow was also manually confirmed to activate without reopening the popup.

Browser tests use fresh isolated profiles and exercise actual MV3 extension code with test-only loopback grants, local generated HTML5 video, recorded playback, dynamically replaced sources, late open Shadow DOM, inherited-origin frames, fullscreen, parent/iframe revocation, reapproval, isolated controls and comparison, compact popup states, accessible full errors, tooltips, WebGPU output readback, native frame pacing, WebGL fallbacks and local tab sharing. Native JW-style control and caption pixels are checked with enhancement active. 0.4 adds checks that the controls frame is sized to its buttons, that sharp sources are skipped, that global pause clears and restores processing with the matching badge, that a toolbar snapshot downloads a PNG without touching playback, that plain `http://` pages get the overlay with the WebGL fallback, and that 300 seeks on a progressive MP4 keep the same renderer. Actual Video.js/Plyr and generated local HLS/DASH media exercise common player integrations. Capture-phase native event handlers verify that extension controls cannot trigger player clicks or shortcuts. API simulations are recorded separately from physical device checks.

Live-player results are in `docs/COMPATIBILITY.md`. A failed or unavailable live player remains blocked or unverified. Physical AMD and Intel devices require separate qualification. For each release, verify native browser restart recovery, denial, parent and overlapping grant removal, and reapproval on the publisher’s installed Chrome profile. Repeat the one-click approval check on the exact package intended for publication. Store availability does not expand the documented compatibility results.

`node scripts/ui-capture.mjs <folder>` captures every popup state, settings section and the in-player toolbar from the built extension for design review; it needs `npm run build` and `npm run dev`.

Package verification recursively inspects the extension ZIP and corresponding-source archive. `npm run verify:release` extracts the actual package and checks all seven settings sections, hidden defaults, no initial grants, popup/gear dimensions, About images/disclosure and viewer/diagnostic entry points without missing resources, page errors or external requests. `npm run verify:source` extracts the bundled corresponding source, runs a fresh `npm ci`, unit tests, build and package, then compares every runtime file byte-for-byte. No private developer files are required. Install browser binaries with `npx playwright install chromium`. Test scripts honor `PLAYWRIGHT_BROWSERS_PATH`, use a project-local `.playwright` cache when present, and otherwise use Playwright's normal cache.
