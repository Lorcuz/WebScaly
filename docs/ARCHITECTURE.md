# Architecture

## Worker (`src/extension/background.ts`)

The Manifest V3 worker owns website approval transactions, configuration, content-script registration, keyboard commands and the per-tab toolbar badge. `permissions.request` starts synchronously in the message listener before storage or queued work. A session-stored intent lets approval finish after the popup closes or the worker restarts; permission denial never creates an approval. Configuration version 2 accepts version-1 imports. Fields added in 0.4 (deband, colour, skip-above, adaptive, preferences) are filled with defaults by normalization, so older configurations and exports keep working.

Writes are serialized; read-only requests (authorization, tab status, reports, removal impact) are answered immediately. `reconcile` keeps a fingerprint of approved scopes and grants in `storage.session`, so a worker that is woken again does not re-broadcast. Session storage is cleared on browser restart, extension reload and update, and the next reconcile is then a full one. Only a change of access re-registers scripts, injects into open tabs and broadcasts `webscaly:refresh`. An invalidation (removal, replace import) always forces the following reconcile to broadcast, so frames that are still approved switch back on. A replace import never widens a kept website beyond the scope already granted, and it does not revoke a grant that still covers a kept website. Settings-only edits reach content scripts through their own storage listener. Removal sends `webscaly:invalidate` before revoking grants, scoped to the removed host patterns (plus `all` for tabs whose page is covered); a frame stops only if a scope covers its origin, and an unscoped message stops every frame. Coverage fails closed: a tab whose URL Chrome no longer reports (after a revocation) and a pattern coverage cannot interpret (`<all_urls>`, a port, `file:`) count as covered (`revokes()` in `src/shared/permissions.ts`). Replace imports and `permissions.onRemoved` scope their invalidation the same way. The frame registry and per-frame badge states live in `storage.session` behind `sessionRecord()`, an atomic queued read-modify-write, so concurrent frames cannot overwrite each other and badge state survives a worker restart. A frame that does not answer a status request is pruned from the registry only if it has not authorized since the request started (an in-memory ordinal; no extra writes), so a player iframe that navigates while the popup or a shortcut asks keeps its entry. A navigation clears the tab's badge and sends `webscaly:resync`, so frames that are still rendering report again.

Commands (`toggle-enhancement`, `toggle-compare`, `cycle-engine`, `snapshot`, `toggle-pause`) resolve the profiles that are actually rendering in the active tab from the frame registry and tab status, apply the change and confirm it with an on-video toast. Content scripts report their state; the worker combines frames into one badge per tab (ON, ! or II).

## Content script (`src/extension/content.ts`)

Each frame authenticates its own origin and the top-level page against profiles and Chrome grants, then caches the result. It re-authorizes on refresh broadcasts and page restore. While it has videos, it also re-authorizes after 30 seconds. The 1.8 s heartbeat does nothing while the page is hidden and scans only when videos are tracked. DOM mutations trigger a scan only when a video or shadow root appears, or when a tracked video or overlay is removed. A video that keeps its renderer through a source change (`videoWidth` briefly 0) is not torn down, and an overlay whose host the page removed is rebuilt. The popup's "player needs access" hint counts only iframes that allow fullscreen and are in view. Storage events apply settings and preferences locally without a worker round trip. Video discovery caches the document and open shadow roots and walks additions in bounded batches. Custom-element hosts that may attach a shadow root later are queued without a ceiling and checked round-robin on each heartbeat (at least 250, then more within a 3 ms budget). It enhances the largest visible decoded video, and a second one only when it is a real player (at least 320×180 and 40% of the largest). Hover previews (below 480×270, muted, and inside a link or looping without controls) get no renderer unless they already have one. Global pause disposes renderers; a disabled site keeps them only while its in-player toolbar is shown.

## Renderer (`src/core/renderer.ts`, `enhancement.ts`)

The renderer follows `requestVideoFrameCallback`, processes each decoded frame once and skips frames while the GPU is still busy, so playback never queues behind it. Its plan comes from the saved settings, the adaptive governor level and battery saver (`src/core/governor.ts`).

- **Adaptive steps.** A step that changes only uniforms (for example quality for Spatial Detail) is applied in place. Only a change of surfaces or networks rebuilds. A stopped session never shows its new canvas before that canvas is configured. Sharpening and colour sliders do not reset the adaptive level.
- **Source size.** Initialization freezes the source size it builds for. A frame of a different size triggers a rebuild.
- **Failures.** A failure that would repeat on every attempt (cross-origin frames) is latched: it is retried only for a new source or from the toolbar. Diagnostics carry a failure `reason` (`protected`, `cross-origin`, `graphics`, `error`), which the popup uses to explain the state and offer the right action.
- **Native video fullscreen.** While the `<video>` element itself is fullscreen, the canvas cannot be shown, so frames are not processed.
- **Shared device.** The WebGPU device is shared and reference-counted. It is destroyed 15 s after the last renderer on the page stops, which frees its GPU memory, and is reused within that window.
- **Display resize.** The source size and the display size are separate. A display change (player resize, fullscreen) settles for 150 ms, then `Enhancement.resize()` replaces only the display-size surface and its bindings inside error scopes; Anime4K adds or drops its 2× stage when the display crosses the working size. The canvas is resized and a frame drawn in the same task, so no blank canvas is shown. A source-size change still rebuilds.
- **Hidden tabs.** A tab hidden for 60 s stops its pipeline (state "waiting") and rebuilds when shown; shorter switches keep everything. A renderer that starts while the tab is already hidden gets the same timer.
- **WebGL context.** A lost context hides the canvas and waits up to 4 s for restoration, then rebuilds on the restored context or reports "graphics"; media events do not start another pipeline while it waits. Destroying a WebGL engine deletes its objects and calls `loseContext()`.

WebGPU pipeline per frame:

1. **Capture:** the external video texture is cropped and resized into the working surface, averaging four taps for large reductions.
2. **Prefilter:** edge-aware denoise and deband into a half-float surface.
3. **Engine:** passthrough for Spatial Detail, or the Anime4K / FSRCNNX networks.
4. **Scale:** to the display size with bilinear, Catmull-Rom or Lanczos-2 (anti-ringing) according to Quality; reductions use a four-tap box. When the enhanced picture already has the output size, every mode is an identity, so this pass and its surface are skipped.
5. **Present:** contrast-adaptive sharpening, vibrance/contrast/brightness and the comparison split, drawn to the canvas over the video.

Engine setup runs inside out-of-memory and validation error scopes, so an allocation failure falls back to Spatial Detail instead of failing on the first frame. FSRCNNX reuses a pass's surface when a later pass saves the same name, and compiles its passes concurrently. The WebGL fallback renders Spatial Detail in one pass with bicubic upscaling and the colour controls. A failed neural initialization falls back to Spatial Detail; device loss retries WebGPU once, then uses WebGL. A non-blocking 96×54 thumbnail readback every three seconds feeds the content hint (`src/core/content-hint.ts`), which only produces suggestions. Snapshots render one frame without the comparison split and read the canvas in the same task.

## Overlay (`src/core/overlay.ts`, `src/ui/frame.ts`)

The canvas, divider, HUD and toasts live in an open shadow root next to the video and never receive pointer input. Layout follows a ResizeObserver, scroll and resize events and a light 500 ms check, not every video frame. Interactive controls are bundled extension frames sized exactly to their content. They fade after 2.6 s without pointer activity but stay hit-testable, so hovering reveals them. The overlay accepts only messages from its own frames, with a per-renderer token and a fixed action schema. Fullscreen from the toolbar uses the player container so the enhanced canvas stays visible.

## Interface (`src/ui`)

Popup and settings share a store hook (`state.ts`) with optimistic updates and debounced slider commits, a small component set (`components.tsx`) and one stylesheet (`styles.css`) in the slate-and-mint palette. Only `ui-frame.html` is web accessible. Fonts, scripts and shaders are bundled; there is no remote code.
